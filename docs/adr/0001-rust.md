# ADR-0001: Rust for daemon, elements and clients

- **Status:** Accepted

## Context
- An existing Python implementation (`nvbroadcast`) reaches about 20 fps on an RTX 5080 Laptop GPU and is heavy on resources.
- The product is a long-running daemon that needs predictable per-frame latency.

## Decision
- Rust for all components: daemon, GStreamer elements, shared crates and CLI.
- NVIDIA SDKs are reached through `bindgen` FFI.

## Consequences
- **Gains:** no GIL and no garbage-collector pauses, a small footprint, a single binary per component, and traits as extension seams.
- **Costs:**
  - FFI wrappers around the C SDKs.
  - CUDA from Rust goes through `cudarc` or GStreamer's CUDA helpers.
- **Caveat:** performance comes mainly from the architecture (frames stay on the GPU; see [ADR-0002](0002-gstreamer-engine.md)), not from the language alone.

## Alternatives considered
- Python (the existing implementation): the frame-rate and resource figures above.
