## Architecture decision records

| ADR | Decision |
|---|---|
| [0001](adr/0001-rust.md) | Rust for daemon, elements, clients |
| [0002](adr/0002-gstreamer-engine.md) | GStreamer (gstreamer-rs) as the media engine |
| [0003](adr/0003-maxine-first-behind-backend-seam.md) | Maxine first, behind an `InferenceBackend` seam |
| [0004](adr/0004-v4l2loopback-first.md) | v4l2loopback is the first sink |
| [0005](adr/0005-dbus-zbus-control-plane.md) | D-Bus via zbus as the control plane |
| [0006](adr/0006-on-demand-gpu-lifecycle.md) | On-demand lifecycle; idle means zero CUDA contexts |
| [0007](adr/0007-headless-daemon-toml-config.md) | Headless daemon with a TOML config file |
| [0008](adr/0008-cpu-ingest-adapters.md) | CPU ingest adapters for MJPEG and YUYV/UYVY |
| [0009](adr/0009-ingest-process-output.md) | Ingest, Process and Output stages joined by a latest-frame slot; the output has a fixed contract and its own clock |
| [0010](adr/0010-phase-locked-output-clock.md) | The output clock locks the phase of its ticks to the camera (timestamps stay on the exact grid), a source switch holds the last frame, and the output queue holds at most 3 frames |
| [0011](adr/0011-daemon-lifecycle-and-dbus-api.md) | Daemon lifecycle (`off`/`idle`/`starting`/`active`/`error`), a persistent loopback writer, consumer detection, runtime state file, and the D-Bus v1 API; amends 0006 and 0007 |
| [0012](adr/0012-video-effects-and-maxine-backend.md) | Video effects (none, blur, replace) in the Process stage as one always-present `obceffect` element, the `InferenceBackend` seam with a dlopen'd Maxine backend, models loaded only while an effect is on, black rather than the raw image while an effect starts or fails, and an `LD_PRELOAD` shim for the SDK's os-release check; extends the D-Bus API to revision 2; amended by 0025: the Maxine backend is part of a loadable module and owns the SDK root; amended by 0027: a repeated frame sends the last processed output, and the failure policy can show an image |
| [0014](adr/0014-mic-noise-removal-filter-chain.md) | Accepted: microphone noise removal as a PipeWire filter-chain hosting a CPU LADSPA plugin (RNNoise by default, DeepFilterNet for higher quality), one dedicated `pipewire -c` process per engine under a template user unit, independent of the daemon; Maxine Audio Effects deferred |
| [0015](adr/0015-cadence-emission-for-sub-rate-inputs.md) | A steady camera slower than the contract (1.1 to 1.9 output periods per frame, such as 20 fps into 30) is followed by emitting each tick at the predicted arrival of its frame; amends 0010 |
| [0016](adr/0016-pipewire-output.md) | An optional native PipeWire `Video/Source` node next to the loopback, fed by a tap on the loopback writer (same stream, pacing and timeline), with three offered formats and CPU conversion; PipeWire links count as consumers; D-Bus revision 3; amends 0004 and 0011 |
| [0017](adr/0017-cuda-checkpoint-parking.md) | The daemon checkpoints its own process with the CUDA checkpoint API when a session has stopped, so Idle after an activation holds no `/dev/nvidia*` fds and no UVM registration; replaces the worker-process fallback; amends 0006 and 0011 |
| [0018](adr/0018-video-noise-removal.md) | Video noise removal (the Maxine `nvvfxdenoising` feature) as a boolean stage that stacks with the effects and runs before them, not a fourth effect; it fails open, because it hides nothing; temporal state is reset by a flag the output clock sets on a new source; D-Bus revision 4; amends 0012 and extends 0011; amended by 0024: the boolean became a list of stages |
| [0019](adr/0019-live-preview.md) | A live preview for clients: a lease (D-Bus revision 5, `AcquirePreview`) that counts as a consumer, small JPEG frames encoded from the writer's tap into a private file in `$XDG_RUNTIME_DIR` and announced with a signal, the `omarchy-broadcast preview` command; extends 0011 and 0016 |
| [0020](adr/0020-camera-image-controls.md) | Per-camera image controls (brightness, contrast, saturation, sharpness, backlight compensation) from a camera-agnostic allowlist, ranges from the device, values stored by camera id and written whenever that camera opens (never to a closed camera), reads in any state, no polling, no restore at close; D-Bus revision 6; extends 0011; amended: every standard control through the settings schema of 0023, inactive controls greyed, `reset_all`/`reset_names`, control events while open |
| [0021](adr/0021-nvidia-sdk-handover.md) | The NVIDIA SDK tooling (os-release shim, packaging, SDK checks) lives in the omarchy-nvidia-sdks repository; omarchy-broadcast keeps only the drop-in, an optional dependency on `maxine-vfx-sdk-local` and a default SDK root; the shim variable is `MAXINE_OS_RELEASE`; amends 0012; amended: the SDK root can come from `[effect] maxine_root`, and the daemon loads the SDK's libraries itself, so `LD_LIBRARY_PATH` is not needed
| [0022](adr/0022-crash-recovery-for-consumers.md) | Crash recovery for consumers: at each loopback writer start the daemon uploads a black timeout image and sets the driver's `timeout`, so Chromium-based applications keep the camera across a daemon crash; the writer stamps with `CLOCK_MONOTONIC`; the unit restarts after 250 ms with an explicit start limit; PipeWire consumers do not survive a crash; extends 0011, amends 0010
| [0023](adr/0023-settings-schema.md) | Camera settings as a tree the daemon describes and computes (groups, typed settings, `enabled` with a human reason, inactive controls shown greyed), D-Bus revision 7 (`GetSettings`, `SetSetting`, `ResetSettings`, `SettingsChanged`, revision and serial), CLI `settings` and `settings_*` JSON lines (`v` stays 1, a settings schema version), writes coalesced and the state saved write-behind, V4L2 control events while the camera is open, the inverted "Keep 30 fps in low light", model-specific behaviour only as data rows keyed by USB VID:PID (the Logitech field of view); extends 0020 and 0011; amended by 0024: the effects join the tree as global settings
| [0024](adr/0024-stackable-stages-and-effects-in-the-settings-schema.md) | Stackable stages: the noise-removal boolean becomes an ordered list (noise removal before the mask, relighting after it, composited over the effect's background), low-resolution enhancement (video super resolution) in the ingest tail before the scale, every stage fails open, features known from the filesystem alone (compute capability cached across restarts); the effects and stages as global settings in the settings tree (D-Bus revision 8, schema still 1); relighting's lighting environments made in code, a blocking stream, a rebuild on a new source; video frame generation, TrueHDR, Upscale and the same-size super-resolution modes not implemented, with the reasons; amends 0018, extends 0023, 0012 and 0009; amended by 0025: stage ids are strings that modules declare; amended by 0027: frame generation is implemented as a stage, the rejection of TrueHDR is kept |
| [0025](adr/0025-loadable-modules.md) | Loadable modules: effects as a manifest and a shared library behind a versioned C ABI (cbindgen header, Rust SDK), discovery from manifests without loading, in-process only, `cuda` and `host` frame kinds with `dmabuf` reserved, string stage ids in slots with a constrained order, backend choice by rank, pin and profile fixed at pipeline start, registry-driven settings with the core `background` group, Maxine as a separately built module that owns its SDK root, zero modules is passthrough, a crash ledger that disables a module after two crashes in a row, ABI version policy (ABI 1.0 not yet frozen); D-Bus revision 9; extends 0012, 0023 and 0024, amends 0012, 0021 and 0024 |
| [0026](adr/0026-config-d-and-managed-config.md) | The configuration is `config.toml` plus the files of `config.d/`, merged key by key; the daemon manages one drop-in, `config.d/50-panel.toml`, and never writes `config.toml`; a config schema (value, source file, `overridden_by`, `editable`, `apply`) and D-Bus revision 10; the module choices move from the state file into the configuration; amends 0007, 0011 and 0025 |
| [0027](adr/0027-output-modes-frame-generation-and-privacy-fallback.md) | Capture and output modes chosen in the panel (the camera's reported modes as a per-camera setting, the output size and rate as an editable enum computed from the camera, a deferred change that names the applications it waits for, a revert order for a format that cannot start, a start without effects that is never used when privacy applies); frame generation as a vendor-neutral stage for an output at twice the camera's rate (never a toggle, one tick of latency); module ABI 1.1 with a repeat flag; the effect element sends its last processed output on a repeat; the privacy switch gains `image` (a still fallback image); TrueHDR still not implemented; D-Bus revision 12; amends 0024 and 0012 |
| [0028](adr/0028-maxine-ar-module.md) | The Maxine AR module: eye contact and auto-framing as two stages of one loadable module with its own SDK root and loading, in the `pre-matte` slot (eye contact first, the order the host gives), both failing open; settings (on/off, look-away, framing; no strength, the SDK's thresholds left alone); auto-framing as a digital zoom in the module for now, with its cost in detail; the two Maxine SDKs in one process |

Conventions: diagrams are mermaid. New decisions get the next ADR number; superseded ADRs keep their file and change their status line.
